# План реалистичной генерации билдов через экипировку

## Зачем нужен этот документ

Сейчас Power Lab генерирует абстрактные билды: каждый стат случайно выбирается из общего диапазона, после чего билды фильтруются по расчетной силе.

Это полезно для стресс-теста формулы силы, но не полностью соответствует будущей игровой системе. В реальной игре характеристики персонажа будут формироваться не произвольно, а через базовые статы героя и экипировку.

Этот документ фиксирует направление, к которому стоит вернуться позже.

## Базовый герой

У героя есть базовые характеристики. На текущий момент:

| Характеристика | Значение |
| --- | ---: |
| `playerBaseHealth` | 100 |
| `playerBaseAttack` | 25 |
| `playerBaseDefence` | 10 |
| `playerBaseSpeed` | 100 |
| `playerBaseCritDamage` | 150 |

Эти значения можно менять в угоду баланса.

Голый герой является минимально возможной боевой единицей. В текущих вводных у голого героя заданы здоровье, атака, defence и скорость. Критический урон `150%` остается базовым значением боевой модели симулятора, если отдельно не будет задано другое правило.

## Экипировка

У героя есть 4 слота экипировки:

| `equipmentType` | Основная характеристика | Боевой стат |
| --- | --- | --- |
| `weapon` | `baseAttack` | Атака |
| `chestarmor` | `baseHealth` | Здоровье |
| `shield` | `baseDefence` | Defence / броня |
| `ring` | `baseGoldMulti` | Небоевая характеристика, в боевой модели не учитывается |

Каждый предмет добавляет основную характеристику сверху к базовым статам героя.

Кольцо не дает боевой primary-стат, но вторичные характеристики на кольцах могут быть боевыми и должны учитываться.

## Вторичные характеристики

У предметов экипировки могут быть вторичные характеристики. Это процентные или специальные боевые параметры, которые уже есть в симуляторе:

| Secondary stat | Стат в симуляторе |
| --- | --- |
| `baseCritRate` | Шанс крита |
| `baseLifeSteal` | Lifesteal |
| `baseMassAttack` | Массовая атака |
| `baseThorns` | Шипы |
| `baseAttackSpeed` | Скорость атаки |
| `baseCritDamage` | Критический урон |

Вторичные характеристики складываются между предметами и добавляются к итоговым статам героя.

Один предмет не может иметь два одинаковых secondary-стата.

Один и тот же secondary-стат может встречаться на разных предметах и стакаться.

Любая вторичная характеристика может появиться на любой экипировке. Ограничений по слотам нет.

## Редкость экипировки

Редкость влияет на две вещи:

1. Размер основной характеристики предмета.
2. Количество и величину вторичных характеристик.

| `equipmentRarityId` | `rarityIndex` | Вторичных характеристик |
| --- | ---: | ---: |
| `common` | 1 | 0 |
| `rare` | 2 | 1 |
| `epic` | 3 | 2 |
| `legendary` | 4 | 3 |

При случайной генерации редкость выбирается по весам:

| `equipmentRarityId` | Вес |
| --- | ---: |
| `common` | 55 |
| `rare` | 25 |
| `epic` | 15 |
| `legendary` | 5 |

Secondary-статы внутри предмета выбираются случайно из доступного списка с равной вероятностью. Отдельных весов выбора для разных secondary-статов нет.

В рамках одного предмета уже выбранный secondary-стат исключается из дальнейшего выбора, чтобы не было дублей.

## Базовые значения статов на экипировке

Базовые значения до применения множителя редкости:

| Стат | Базовое значение |
| --- | ---: |
| `baseHealth` | 10 |
| `baseAttack` | 2.5 |
| `baseDefence` | 1 |
| `baseCritRate` | 10 |
| `baseLifeSteal` | 12 |
| `baseMassAttack` | 8 |
| `baseThorns` | 15 |
| `baseAttackSpeed` | 10 |
| `baseCritDamage` | 20 |

Эти значения считаются черновыми. Они были заданы как стартовые и должны быть пересчитаны через отдельный балансировочный эксперимент secondary-статов.

Формула роста основных и вторичных характеристик от редкости:

```text
statValue = baseStat * rarityStatsIncreaseCoeff^(rarityIndex - 1)
rarityStatsIncreaseCoeff = 1.2
```

После применения множителя редкости значения округляются:

- если значение ниже `20`, округляем до `1` знака после запятой;
- если значение `20` или выше, округляем до целого.

Для `legendary` из таблицы `rarityIndex = 4`, поэтому степень равна `3`:

```text
legendaryMultiplier = 1.2^(4 - 1) = 1.728
```

Пример максимальных значений на одной легендарной экипировке:

| Стат | Значение |
| --- | ---: |
| `baseHealth` | 17.28 |
| `baseAttack` | 4.32 |
| `baseDefence` | 1.728 |
| `baseCritRate` | 17.28 |
| `baseLifeSteal` | 20.736 |
| `baseMassAttack` | 13.824 |
| `baseThorns` | 25.92 |
| `baseAttackSpeed` | 17.28 |
| `baseCritDamage` | 34.56 |

После округления по правилу выше:

| Стат | Округленное значение |
| --- | ---: |
| `baseHealth` | 17.3 |
| `baseAttack` | 4.3 |
| `baseDefence` | 1.7 |
| `baseCritRate` | 17.3 |
| `baseLifeSteal` | 21 |
| `baseMassAttack` | 13.8 |
| `baseThorns` | 26 |
| `baseAttackSpeed` | 17.3 |
| `baseCritDamage` | 35 |

## Минимум и максимум силы

Минимальная сила:

```text
голый герой
```

Максимальная сила:

```text
герой + 4 легендарных предмета
```

При этом максимум зависит не только от редкости, но и от удачности вторичных характеристик. Например, персонаж с четырьмя легендарными предметами может получить разные боевые профили в зависимости от того, выпали ли ему шанс крита, lifesteal, шипы, скорость атаки и другие параметры.

## Как это меняет Power Lab

Текущий Power Lab работает так:

```text
случайные независимые статы
-> расчет силы
-> фильтр по targetPower
-> бои 1 на 1
```

Для будущей системы нужен дополнительный режим:

```text
базовый герой
-> генерация экипировки
-> расчет итоговых статов
-> расчет силы
-> бои 1 на 1
```

Важно: текущий режим все еще полезен как стресс-тест формулы. Новый режим нужен для проверки реалистичных билдов, которые действительно могут появиться в игре.

## Предлагаемые режимы Power Lab

### Formula Stress Lab

Текущий режим.

Назначение:

- проверять формулу силы на широких и искусственных комбинациях;
- искать математические перекосы;
- быстро видеть, какие статы формула переоценивает или недооценивает.

Ограничение:

- может создавать билды, которые невозможны или маловероятны в реальной системе экипировки.

### Gear Realistic Lab

Новый будущий режим.

Назначение:

- генерировать билды через реальные правила героя и экипировки;
- проверять баланс не абстрактных статов, а игровых персонажей;
- оценивать разброс силы из-за удачных и неудачных вторичных статов;
- сравнивать персонажей внутри одного уровня экипировки;
- сравнивать персонажей внутри одной итоговой силы.

## Балансировка secondary-статов

Отдельная важная задача перед полноценным Gear Realistic Lab: подобрать базовые значения secondary-статов так, чтобы разные secondary-статы давали сопоставимую прибавку силы.

Пример целевого поведения:

```text
Есть редкая экипировка с одним secondary-статом.
Если на ней выпал baseCritRate, baseLifeSteal, baseMassAttack, baseThorns, baseAttackSpeed или baseCritDamage,
то итоговая сила персонажа должна быть примерно одинаковой.
```

Это не означает, что все secondary-статы должны иметь одинаковые численные значения. Наоборот, базовые значения должны быть разными, потому что каждая характеристика по-разному влияет на бой.

Практический подход:

```text
1. Берем базового героя.
2. Надеваем один и тот же предмет одной и той же редкости.
3. Меняем только один secondary-стат.
4. Считаем изменение силы.
5. Подбираем base value каждого secondary-стата так, чтобы прирост силы был близким.
6. Проверяем результат симуляциями, потому что формула силы может ошибаться.
```

Для одной secondary-характеристики отклонение прироста силы должно быть небольшим. Как стартовый ориентир можно считать хорошим результатом разброс в пределах `5-10%` между secondary-статами одной редкости. Если какой-то secondary-стат системно выходит за этот диапазон, его базовое значение стоит пересчитать.

Это нужно сделать до того, как использовать Gear Realistic Lab для выводов о балансе билдов. Иначе генератор будет отражать не только силу формулы, но и перекосы в самих базовых значениях secondary-статов.

## Пример будущей генерации

```text
1. Создать голого героя.
2. Сгенерировать оружие, броню, щит и кольцо.
3. Для каждого предмета определить редкость.
4. По редкости выдать основную характеристику.
5. По редкости выбрать 0-3 вторичных характеристики.
6. Сложить все характеристики в итоговый CombatantStats.
7. Посчитать силу через calculatePower.
8. Провести серию боев против других реалистичных билдов.
```

## Оставшиеся открытые вопросы

- Нужны ли ограничения secondary-статов по слотам. Сейчас ограничений нет, но их можно ввести позже, если появятся причины по балансу или дизайну.
- Какие финальные базовые значения secondary-статов получатся после отдельного балансировочного эксперимента.

## Важный вывод

Подход к расчету силы пока можно продолжать балансировать на текущем Power Lab, но для проверки реального игрового баланса понадобится генератор, основанный на экипировке.

Иначе есть риск балансировать формулу на персонажах, которых игроки почти никогда не смогут собрать.
